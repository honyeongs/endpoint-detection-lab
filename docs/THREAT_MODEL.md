# 위협 모델

## 자산과 공격자 입력

사용자가 선택한 이벤트의 기밀성, 로컬 컴퓨터 자원, 탐지 근거·프로세스 관계의 정확성.
공격자가 XML·JSON 파일 내용, 파일명, 이벤트 메타데이터, 외부 웹 페이지를 통제한다고 가정한다.

## 방어

- 파일 -> 파서: 일반 파일 스냅샷, 크기·필드·이벤트 한도, DTD·엔터티 금지, JSON 중복 키와 잘못된 타입 거부.
- 이벤트 -> 연결: UTC 정렬, 정확한 중복 제외, 호스트 + GUID 분리, 부모 누락 표시, 잘못된 시간·순환 관계 경고.
- 연결 -> 탐지: 필요한 생성 이벤트 없는 네트워크 연결을 추정하지 않고, 필드·시간·같은 호스트 조건을 근거에 남긴다.
- 정책 -> 결과: 정확 일치 조건만 허용하고 제외된 탐지도 기록한다. 규칙·호스트·명령줄 범위를 확인할 수 있다.
- 입력 -> 화면: DOM 텍스트 API, 제어 문자 가시화, 자체 리소스만 허용하는 CSP.
- 브라우저 -> API: 루프백, Host·Origin 검증, 고정 경로, 본문 길이·형식·시간 제한.
- 보고서 -> 공개 저장소: 자동 저장 없음, 원본 로그 제외, 합성 표본 일치·자산 고지·비밀 패턴 공개 전 검사.

## 해결하지 않는 문제

로그 진본성, 수집 단계의 변조·누락, 실제 페이로드 악성 여부, 커널·드라이버 신뢰,
다른 로컬 사용자 공격, 대규모 서비스 DoS, 광범위한 행위 분석, 상용 EDR 우회 방지.
파일 경로가 같아도 실제 파일 내용이 같은지는 알 수 없다.
기본·조정 정책 비교는 같은 자체 합성 표본에 대한 기능 검증이며 독립 평가 데이터 성능이 아니다.
