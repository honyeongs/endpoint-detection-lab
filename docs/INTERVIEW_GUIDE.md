# 면접 시연 가이드

## 3분 시연

1. 첫 합성 사건에서 이벤트 8개, 프로세스 5개, 탐지 5개를 확인한다. 실제 공격을 실행한 것이 아닌 합성 메타데이터임을 먼저 밝힌다.
2. 재생 슬라이더를 3으로 옮긴다. 아직 실행되지 않은 파일에 대한 실행 탐지가 없음을 보여준다.
3. 다음 이벤트를 누른다. 임시 실행 파일과 생성→실행 시간 상관 규칙 두 개가 나타난다.
4. 사건을 클릭해 규칙 ID, 시간 차이, 일치 필드, 관련 이벤트, 정상 작업 가능성을 설명한다.
5. 프로세스 트리에서 문서 프로그램→PowerShell 관계를, 타임라인에서 후속 연결을 확인한다.
6. 규칙 검증에서 정상 관리 작업으로 발생한 FP 2개와 정확 일치 정책 적용 후 결과를 비교한다. 합성 표본 성능임을 명시한다.
7. 실제 XML 형식의 합성 표본을 가져오고 JSON 보고서를 저장한다. 원격 CI와 보안·출처 문서를 연다.

## 설명할 설계 결정

- **왜 PID가 아닌 GUID인가?** PID는 재사용된다. 같은 호스트의 ProcessGuid를 연결 키로 사용하고 다른 호스트와 섞지 않는다.
- **왜 시간 정렬과 중복 제외를 하는가?** 내보내기 순서에 의존하지 않고 같은 이벤트 중복으로 경고를 부풀리지 않기 위해서다.
- **왜 누락된 부모를 표시하는가?** 존재하지 않는 프로세스 관계를 정상 데이터처럼 추정하지 않기 위해서다.
- **왜 DTD를 금지하는가?** 로그 포맷에 필요하지 않은 엔터티와 외부 참조를 제거해 XML 공격면을 줄인다.
- **왜 오탐 예외를 정확 일치로 제한하는가?** 광범위한 와일드카드·정규식 예외가 탐지를 숨기지 않도록 범위를 드러내기 위해서다. 정확 일치도 공격자가 흉내 낼 수 있다.
- **왜 높은 징후를 우선 보존하는가?** 상세 목록 한도를 넘겨도 높은 위험 근거가 낮은 위험 항목에 밀리지 않도록 하기 위해서다.
- **왜 탐지 없음이 안전이 아닌가?** 입력의 이벤트 유형과 규칙 범위가 제한되고 로그 진본성·페이로드를 검사하지 않기 때문이다.

## 검증 근거와 정직한 한계

단위·HTTP·브라우저 테스트, 자체 합성 정답 manifest, 원격 CI, 자산 체크섬을 근거로 제시한다.
현재는 실제 공격·실제 Sysmon 수집 실험·침투 테스트·현장 탐지율 측정을 수행한 프로젝트가 아니다.
AI 개발 지원을 활용했음을 숨기지 말고, 직접 이해하고 설명하거나 수정·재현한 부분을 구체적으로 말한다.
이 문서의 설계 설명을 본인의 경험처럼 암기하기보다 테스트를 바꾸고 결과를 확인하면서 이해해야 한다.
